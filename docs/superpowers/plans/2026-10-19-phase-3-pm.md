# Compass Phase 3 (PM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compass becomes a PM tool: each project has its RAID log, change requests, decisions and lessons; a portfolio shows every project's health; an offline PM library answers questions; a copilot on Claude or Gemini works inside each project's data boundary and can put its plan on the board; Word, Markdown and PDF documents (built-in templates, your own `.docx` templates, the one-tap status report) are generated on the device.

**Architecture:** Four new governance tables hang off `projects`, encrypted like every work row. The library is Markdown in `worker/library/`, compiled at build time into one JSON bundle that both the Worker (copilot retrieval) and the device (offline search) index with the same small inverted-index module in `shared/`. The copilot is one route, `POST /api/ai/chat`, that refuses an offline-boundary project before any model call, builds a fenced prompt from library hits and the project record, calls Anthropic or Gemini over `fetch`, and stores the answer with validated citations and proposals. Documents are uploaded to R2 (sealed for work projects); generation happens in the browser with `docx` and `docxtemplater`.

**Tech Stack:** As Phases 1–2, plus `unpdf` and `fflate` (Worker: text from PDF and Word) and `docx`, `docxtemplater`, `pizzip` (web: Word generation and template filling). Model calls are plain `fetch` to `api.anthropic.com` and `generativelanguage.googleapis.com` (no SDK).

**Spec:** `docs/superpowers/specs/2026-10-19-compass-design.md` (§3 raid_items, change_requests, decisions, lessons, library_pages, documents, ai_threads, ai_messages; §4 governance, portfolio, library, documents, ai, reports, export routes; §5.4 RAID from meetings; §6 Projects/Project, Library, Copilot; §7 all; §12; §13 step 3; §14). Catalogue: `docs/compass-features.md` §1 (use-cases, documents, templates, data boundary), §5, §6 (minutes), §7, §8, §9.

## Global Constraints

- Everything from the Phase 1 and Phase 2 plans' Global Constraints still holds (domain, ids, tokens, ISO timestamps, no hard delete from the API, work-row encryption, `COMPASS_USERS`, same-origin, self-checks, typecheck before every commit, plain text never rendered as HTML).
- Dependencies: Phase 2's list plus `unpdf`, `fflate` (Worker; `fflate` may also be used in web), `docx`, `docxtemplater`, `pizzip` (web). Nothing else: no Markdown library, no chart library, no AI SDK.
- Every new table with user text has `enc_v`; on a row that belongs to a work project its text columns are sealed (`ENC_COLS`, AAD `table.column`). A row's kind is its project's kind; a copilot thread with no project is personal.
- Data boundary is enforced in the Worker: a model call that would carry anything from a project whose `data_boundary = 'offline'` is refused before the call (HTTP 409, `{ error: 'offline_boundary' }`). Changing a project's boundary needs the passkey step-up and is audited.
- Every AI call names a feature (`copilot`, `status_report`, `plan_review`, `brief`), is checked against the month's cap first (`settings.ai_monthly_cap_micro`), is recorded in `ai_usage` with tokens and cost, and is audited without content. `POST /api/ai/chat` is limited to 30 calls per hour.
- Notification, email, transcript and imported-document text placed in a prompt sits inside a fenced data block (`fence()`); the system prompt says data blocks are never instructions.
- Model output is checked against a schema before use; nothing from a proposal is written until Vlad taps "Add to the board".
- Library pages are written in Compass's own words: no copied text from PMBOK, PRINCE2, the Scrum Guide, SAFe or any other source, and no quotation longer than 15 words.
- Documents are generated on the device. Uploads are type- and size-checked and streamed privately from R2; a work project's files are sealed in R2.
- Model ids, prices and keys are settings: `AI_MODEL_CLAUDE`, `AI_MODEL_GEMINI`, `AI_PRICES` (wrangler vars), `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` (secrets, put by Vlad only).
- Commit trailer: the implementer's own model attribution line.

## Rulings made while writing this plan

- **R1 Library search is one shared inverted index, not D1 FTS5** (spec §3 says `library_fts`). `shared/search.ts` runs on the device (offline search) and in the Worker (copilot retrieval), so both find the same pages. Bundled pages compile into JSON at build time; D1 `library_pages` holds only your imports. Cost if wrong: add FTS5 once imports pass a few thousand pages.
- **R2 Search over your own data runs on the device** (spec §4 lists `GET /search`). The palette already has tasks and projects in IndexedDB; it adds the library index and the documents list. Work content never enters a server index (spec §12), and there is no `/api/search`. Cost: none.
- **R3 Governance logs act online only**, cached per project in IndexedDB `meta` for offline reading, as Phase 2 did for the inbox (P7). Tasks, projects and milestones keep the offline write queue. Cost if wrong: a later phase adds them to the queue.
- **R4 Copilot answers are not streamed** in Phase 3 (one JSON reply, `max_tokens` 2000, a typing indicator). Cost: a few seconds of waiting on long answers.
- **R5 An answer's citations and proposals travel in a trailing fenced block** (` ```compass-meta ` holding JSON) that the Worker strips, validates and stores in their own columns. An invalid block is dropped and the answer kept. Cost: none.
- **R6 Models**: `AI_MODEL_CLAUDE = "claude-sonnet-5-5"` (the newest Sonnet; spec said `claude-sonnet-5` because Knocturn ID's notes use it, and Task 13's live check falls back to `claude-sonnet-5` if the newer id is refused) and `AI_MODEL_GEMINI = "gemini-3.6-flash"` (the Gemini model Kelly has confirmed working). Prices are a var, `AI_PRICES`, in USD per million tokens, so a price change is a config edit.
- **R7 The monthly cap defaults to US$20** (`ai_monthly_cap_micro: 20000000`), editable in Settings. The month is the calendar month in `settings.tz`. Cost if wrong: one settings edit.
- **R8 Library imports are personal only.** An upload filed under a work project stays a project document (sealed, never indexed); only personal or unfiled documents can be added to the library, which the copilot may cite. Cost: Bell reference documents can't be searched in the library yet; a later version can add a device-only work index.
- **R9 Kelly's document pipeline ("index with Kelly") waits for Phase 5**, when Compass and Kelly share scopes. Phase 3 extracts text in the Worker (`unpdf`, `fflate` + the Word XML).
- **R10 Built-in templates are code**, one `docx` builder per template, not stored `.docx` files. Your own templates are uploaded `.docx` files with `{{…}}` placeholders, filled by `docxtemplater`. Spec §7's eight built-ins plus meeting minutes (catalogue §6, v1).
- **R11 Export lands in Phase 3** because no earlier phase built it: `GET /api/export` (passkey) returns the decrypted JSON bundle; the device turns it into a Markdown zip too.
- **R12 RAID from meetings** (Phase 2 ruling P8 deferred it): the meeting review offers "Add as risk" / "Add as issue" on open questions and important notes; accepted ones become RAID items with `from_meeting_id`.
- **R13 Markdown is rendered by a small hand-written parser** into React elements (headings, lists, tables, code, quotes, bold, italic, links). No HTML passes through; links are `https:` or in-app `[[slug]]`.
- **R14 "Second read"**: under an answer, "Ask Gemini too" (or Claude) re-runs the same question with the other model in the same thread.
- **R15 Today's brief** is Compass's own one-paragraph summary, computed on the device with no AI. "Write it with the copilot" sends only personal tasks and tasks of cloud-boundary projects; offline-boundary work is counted, never named. Kelly's brief is Phase 5.
- **R16 Trash covers the new rows**: RAID items, change requests, decisions, lessons, documents and copilot threads go to Trash on delete, can be restored, and are purged after 30 days; purging a project purges its governance rows, documents (and their R2 objects) and threads first.

```ts
export interface SearchDoc { id: string; title: string; body: string; section?: string }
export interface SearchIndex<D extends SearchDoc = SearchDoc> { docs: D[]; post: Map<string, Map<number, number>>; len: number[]; avg: number }

const STOP = new Set(('a an and are as at be by for from has have how i in is it its of on or that the this to was what when where which who why will with ' +
  'au aux ce ces dans de des du elle en est et il la le les ne par pas pour que qui sa se ses son sur un une').split(' '));
export const fold = (s: string) => s.normalize('NFD').replace(/\p{M}/gu, '').toLowerCase();
// ponytail: plural-s strip only (EN and FR); add a real stemmer if recall disappoints.
const stem = (w: string) => (w.length > 3 && w.endsWith('s') && !w.endsWith('ss') ? w.slice(0, -1) : w);
export const tokens = (s: string) => fold(s).split(/[^\p{L}\p{N}]+/u).filter((w) => w.length > 1 && !STOP.has(w)).map(stem);

export function buildIndex<D extends SearchDoc>(docs: D[]): SearchIndex<D> {
  const post = new Map<string, Map<number, number>>(), len: number[] = [];
  docs.forEach((d, i) => {
    const title = tokens(d.title);
    const all = [...title, ...title, ...title, ...tokens(d.section ?? ''), ...tokens(d.body)]; // title counts three times
    len.push(all.length);
    for (const t of all) { let m = post.get(t); if (!m) post.set(t, (m = new Map())); m.set(i, (m.get(i) ?? 0) + 1); }
  });
  return { docs, post, len, avg: len.reduce((a, b) => a + b, 0) / (len.length || 1) };
}

/** BM25 (k1 1.2, b 0.75). The last query word also matches as a prefix unless the query ends with a space. */
export function search<D extends SearchDoc>(ix: SearchIndex<D>, q: string, limit = 10): { doc: D; score: number }[] {
  const words = [...new Set(tokens(q))];
  if (!words.length) return [];
  const N = ix.docs.length, score = new Map<number, number>();
  words.forEach((w, k) => {
    const prefix = k === words.length - 1 && !/\s$/.test(q);
    const terms = prefix ? [...ix.post.keys()].filter((t) => t.startsWith(w)) : ix.post.has(w) ? [w] : [];
    for (const t of terms) {
      const m = ix.post.get(t)!, idf = Math.log(1 + (N - m.size + 0.5) / (m.size + 0.5));
      for (const [i, f] of m) score.set(i, (score.get(i) ?? 0) + idf * (f * 2.2) / (f + 1.2 * (0.25 + 0.75 * ix.len[i] / ix.avg)));
    }
  });
  return [...score].sort((a, b) => b[1] - a[1]).slice(0, limit).map(([i, s]) => ({ doc: ix.docs[i], score: s }));
}

/** The sentence holding most query words, cut to max characters. */
export function snippet(body: string, q: string, max = 180): string {
  const want = new Set(tokens(q));
  const sentences = body.replace(/[#>*_`|]/g, ' ').split(/(?<=[.!?])\s+|\n+/).map((s) => s.trim()).filter(Boolean);
  let best = sentences[0] ?? '', most = -1;
  for (const s of sentences) { const n = tokens(s).filter((t) => want.has(t)).length; if (n > most) { best = s; most = n; } }
  return best.length > max ? best.slice(0, max - 1) + '…' : best;
}
```

```ts
import type { Proposals, Horizon, RaidType } from './types.ts';

const BLOCK = /\n?```compass-meta[ \t]*\n([\s\S]*?)\n?```\s*$/;
const HORIZONS: Horizon[] = ['short', 'medium', 'long'];
const RAID: RaidType[] = ['risk', 'assumption', 'issue', 'dependency'];
const str = (v: unknown, max: number) => (typeof v === 'string' && v.trim() && v.trim().length <= max ? v.trim() : null);
const level = (v: unknown) => (Number.isInteger(v) && (v as number) >= 1 && (v as number) <= 5 ? (v as number) : null);
const ymd = (v: unknown) => (typeof v === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(v) && !Number.isNaN(Date.parse(v)) ? v : null);
const list = (v: unknown): Record<string, unknown>[] => (Array.isArray(v) ? v.filter((x) => x && typeof x === 'object').slice(0, 20) : []);

export const isEmpty = (p: Proposals) => !p.tasks.length && !p.raid.length && !p.decisions.length;

/** Model output is data until checked: the trailing compass-meta block is parsed, every item validated, the rest dropped. */
export function splitAnswer(raw: string, known: Set<string>): { content: string; citations: string[]; proposals: Proposals } {
  const m = raw.match(BLOCK);
  const content = (m ? raw.slice(0, m.index) : raw).trim();
  let meta: Record<string, unknown> | null = null;
  try { const v = m ? JSON.parse(m[1]) : null; meta = v && typeof v === 'object' ? v : null; } catch { meta = null; }
  const p = (meta?.proposals && typeof meta.proposals === 'object' ? meta.proposals : {}) as Record<string, unknown>;
  const citations = [...new Set((Array.isArray(meta?.citations) ? meta.citations : []).filter((s): s is string => typeof s === 'string' && known.has(s)))].slice(0, 8);
  return {
    content,
    citations,
    proposals: {
      tasks: list(p.tasks).flatMap((t) => { const title = str(t.title, 120); return title ? [{ title, horizon: HORIZONS.includes(t.horizon as Horizon) ? (t.horizon as Horizon) : 'short', due_at: ymd(t.due_at) }] : []; }),
      raid: list(p.raid).flatMap((x) => { const text = str(x.text, 2000); return text && RAID.includes(x.type as RaidType) ? [{ type: x.type as RaidType, text, probability: level(x.probability), impact: level(x.impact) }] : []; }),
      decisions: list(p.decisions).flatMap((d) => { const text = str(d.text, 2000); return text ? [{ text }] : []; }),
    },
  };
}
```
