# Compass v2.5 (Time tracking) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Timers and manual time entries on tasks and projects, working offline and on every device, with actual-against-estimate, Workload's past weeks, a Time screen with CSV export, hours in the status report, and start/stop from the widgets.

**Architecture:**
- **Schema:** one migration, `0018_time.sql`: table `time_entries`.
- **Sync:** entries live in the device mirror (a new IndexedDB store `time`), pulled incrementally like tasks; start, stop, edit and delete go through the offline queue.
- **Computed on the device:** every total (task, project, program, accuracy, Workload past weeks, the timesheet) is a pure function in `shared/time.ts`.
- **Server-side:** the routes, the forgotten-timer cron (4 h push, 12 h auto-stop), and a second widget-token action.

**Tech Stack:** As before (Hono on Workers + D1, React + Vite, plain CSS with tokens, Capacitor Swift and Java widgets). No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-25-v2-5-time-design.md` (approved by Vlad on 2026-10-25). Read it with this plan.

## Rulings made while writing this plan

- **T1: one table, two owners.** An entry has `task_id` xor `project_id` (CHECK `(task_id IS NULL) != (project_id IS NULL)`): a task entry keeps `project_id` null and follows its task's current project; a project entry has no task and a required note.
- **T2: kind at creation.** `kind` is copied from the task (or project) when the entry is created and never changes; sealing follows it. A task's kind can't change after creation in practice (a project move can change it: if the task's kind differs from the entry's at an edit, the edit re-seals by the entry's own kind; totals still follow the task).
- **T3: clamps.** `clampTs(s, nowMs)` → ISO within `[2020-01-01T00:00:00.000Z, now + 5 min]`; a start after the clamp's ceiling becomes the ceiling. Duration cap 24 h checked after clamping (`MAX_ENTRY_MINUTES = 1440`). Shared in `shared/time.ts` so the device shows the same answer the server gives.
- **T4: stop.** `POST /api/time/:id/stop {ended_at}`: clamp, then `ended_at = max(clamped, started_at)`, then cap at `started_at + 24 h`; `UPDATE time_entries SET ended_at = ?2, updated_at = ?3 WHERE id = ?1 AND ended_at IS NULL AND deleted_at IS NULL`; zero changes → 200 with the stored row (already stopped) or 404 if missing/trashed.
- **T5: queue.** `Entity` gains `'time'`; a start or manual entry is queued with a temp id and an optimistic row; the reply key is `reply.entry`. Stop is queued as `POST /time/<id>/stop` with the device's `ended_at`. The optimistic stop writes `ended_at` locally at once.
- **T6: pull.** `pull()` adds `/time?since=<meta.last_pull_time>` (own mark, server clock = max `updated_at` seen) and `applyPlan('time', …, false)`.
- **T7: cron.** In `pushes(env, at)`: `notifyTimers(env, at)`:
  - auto-stop first: `UPDATE time_entries SET ended_at = <started_at + 12 h>, auto_stopped = 1, updated_at = ? WHERE ended_at IS NULL AND deleted_at IS NULL AND started_at <= ?(now − 12 h)` (computed in SQL with `strftime('%Y-%m-%dT%H:%M:%fZ', started_at, '+12 hours')` — the one place a SQL time function is allowed, because it derives from a stored ISO value, not "now"; `updated_at` is the JS ISO now);
  - then the 4 h nudge: `SELECT id FROM time_entries WHERE ended_at IS NULL AND deleted_at IS NULL AND started_at <= ?(now − 4 h) LIMIT 50`; for each id whose `push_outbox` key `timer:<id>:4h` is absent and when `settings.push.timer` is on and not quiet hours: `deliver(env, { title: 'Compass', body: 'A timer has been running 4h', url: '/time' }, 'timer:<id>:4h')`.
- **T8: widget action.** `POST /api/widget/tasks/:id/timer {action, at}`: token check as `/done` (401 rules, limits 429, `last_used_at`); task must be live and not done (404 audited refused); `start` → same insert as `POST /api/time` with `source = 'widget'` (409s audited refused); `stop` → stops the task's running entry (none running → 200 `{ ok: true, stopped: false }`); audit `widget.timer` `{ token, action, ok }`. Pending file entries become `{ id, at, action? }` (`action` absent = done tick, so old files still read).
- **T9: Workload past weeks.** `actualWeeks(entries, tasks, s, today, tz, n = 4, filter?)` → `WWeek[]` for the n weeks before `weekStart(today)`, `work`/`personal` entries per project from `splitByDay`, capacity from `overrides[w] ?? defaults` (no pro-rating: past weeks are whole). The screen draws them before the planned weeks, labelled "Actual".
- **T10: report.** `buildReportModel` gains `time: { logged_minutes: number; done_logged_minutes: number; done_estimated_minutes: number } | null` for the report's range; the program report model gains `minutes` per project row. `reportText` and `programReportText` add the numbers ("Time logged this period: 12h 30m; done tasks: 9h of 8h estimated").
- **T11: purge order.** In the Trash purge batch, `DELETE FROM time_entries WHERE (deleted_at IS NOT NULL AND deleted_at < ?1) OR task_id IN (goneTasks) OR project_id IN (goneProjects)` runs before the tasks and projects deletes.
