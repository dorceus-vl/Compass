# Compass v2.6 (Goals and OKRs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Personal and work goals with key results (number, tasks, done, percent), a quarter or free dates, tasks and projects linked to key results, check-ins with history and confidence, progress against the period's expected progress, shown on a Goals screen, a goal page, Today's long horizon and the Weekly Review.

**Architecture:**
- **Schema:** one migration, `0019_goals.sql`: tables `goals`, `key_results`, `goal_links`, `goal_checkins`.
- **Sync:** all four live in the device mirror (new IndexedDB stores), pulled incrementally from one endpoint; every edit goes through the offline queue.
- **Computed on the device:** every progress figure (key result, goal, expected, confidence, trend) is a pure function in `shared/goals.ts`.
- **Server-side:** the routes, caps, kind checks, sealing, Trash, purge and export. No cron, no push.

**Tech Stack:** As before (Hono on Workers + D1, React + Vite, plain CSS with tokens). No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-25-v2-6-goals-design.md` (approved by Vlad on 2026-10-26). Read it with this plan.

## Rulings made while writing this plan

- **G1: every table syncs.** `goal_links` and `goal_checkins` get `updated_at` (the spec listed only `created_at`) so `?since=` works the same for all four.
- **G2: Trash by parent.** Trashing a goal sets `deleted_at` on the goal only; its key results, links and check-ins are hidden because their goal is gone (server reads and `shared/goals.ts` both filter on a live goal) and come back with it. Same for a key result and its links and check-ins. Trash lists goals and key results; links and check-ins are not listed.
- **G3: values per type.** `number`: `start_value`, `target_value`, `current_value` (starts at `start_value`), `unit`. `percent`: start 0, target 100. `done`: start 0, target 1, current 0 or 1. `tasks`: all three null. The CHECK `start_value != target_value` applies when both are set.
- **G4: a check-in moves the value.** `POST /api/goals/krs/:id/checkins {value?, confidence, note?, at}` inserts the check-in and, for `number`, `percent`, `done`, sets `key_results.current_value` and `updated_at` in the same `DB.batch`. `value` is required for those types and must be null for `tasks` (400 `bad_checkin`). `at` is clamped with `clampTs` from `shared/time.ts`. A wrong check-in is fixed by a newer one or `DELETE /api/goals/checkins/:id` (soft).
- **G5: caps inside the INSERT,** as `programs.ts:41-44`: 10 live key results per live goal (409 `kr_limit`), 200 live links per key result (409 `link_limit`); a restore of a key result re-checks `kr_limit`. Partial unique indexes on live `(kr_id, task_id)` and `(kr_id, project_id)`; a duplicate is 409 `link_exists`.
- **G6: kind check.** A link's task or project must be live and of the goal's kind (409 `goal_kind`); a goal's `kind` is not in the PATCH whitelist.
- **G7: one pull.** `GET /api/goals?since=` → `{ goals, krs, links, checkins }` (with `since`, rows with `updated_at >= since`, trashed included; without, live rows); the device keeps `meta.last_pull_goals` (server clock = max `updated_at` across the four). Entities `'goals' | 'krs' | 'goal_links' | 'checkins'`; reply keys `reply.goal`, `reply.kr`, `reply.link`, `reply.checkin`.
- **G8: purge.** In the Trash batch, before tasks and projects: `goal_checkins` and `goal_links` whose own `deleted_at` is past 30 days, or whose key result or goal is gone (`goneKrs`, `goneGoals` subselects), or whose task or project is in `goneTasks` / `goneProjects`; then `key_results`; then `goals`.
- **G9: nav.** `NAV` gains `['goals', '/goals', 'Goals']` after Projects (there is no Programs entry); Palette `JUMPS` gains `/goals`; the router maps `goals/:id` to `goal`.
- **G10: expected progress.** `expected(goal, today)` = `days(starts_on → today) / days(starts_on → ends_on)`, clamped to 0..1, using local dates from `settings.tz`. "Behind" when progress < expected − 0.1.

- [ ] **Step 1: Migration.**
  ```sql
  -- 0019_goals.sql (v2.6): goals with key results, links to tasks or projects, and check-ins.
  CREATE TABLE goals (
    id TEXT PRIMARY KEY, kind TEXT NOT NULL CHECK (kind IN ('personal','work')),
    title TEXT NOT NULL, description TEXT, starts_on TEXT NOT NULL, ends_on TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','achieved','missed','dropped')),
    sort REAL NOT NULL DEFAULT 0, enc_v INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT,
    CHECK (starts_on <= ends_on)
  );
  CREATE TABLE key_results (
    id TEXT PRIMARY KEY, goal_id TEXT NOT NULL REFERENCES goals(id), title TEXT NOT NULL,
    type TEXT NOT NULL CHECK (type IN ('number','tasks','done','percent')),
    start_value REAL, target_value REAL, current_value REAL, unit TEXT,
    sort REAL NOT NULL DEFAULT 0, enc_v INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT,
    CHECK (start_value IS NULL OR target_value IS NULL OR start_value != target_value)
  );
  CREATE TABLE goal_links (
    id TEXT PRIMARY KEY, kr_id TEXT NOT NULL REFERENCES key_results(id),
    task_id TEXT REFERENCES tasks(id), project_id TEXT REFERENCES projects(id),
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT,
    CHECK ((task_id IS NULL) != (project_id IS NULL))
  );
  CREATE TABLE goal_checkins (
    id TEXT PRIMARY KEY, kr_id TEXT NOT NULL REFERENCES key_results(id), value REAL,
    confidence TEXT NOT NULL CHECK (confidence IN ('on_track','at_risk','off_track')),
    note TEXT, at TEXT NOT NULL, enc_v INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT
  );
  CREATE INDEX goals_sync ON goals (updated_at);
  CREATE INDEX krs_sync ON key_results (updated_at);
  CREATE INDEX krs_goal ON key_results (goal_id);
  CREATE INDEX links_sync ON goal_links (updated_at);
  CREATE INDEX links_task ON goal_links (task_id);
  CREATE INDEX links_project ON goal_links (project_id);
  CREATE UNIQUE INDEX links_kr_task ON goal_links (kr_id, task_id) WHERE deleted_at IS NULL AND task_id IS NOT NULL;
  CREATE UNIQUE INDEX links_kr_project ON goal_links (kr_id, project_id) WHERE deleted_at IS NULL AND project_id IS NOT NULL;
  CREATE INDEX checkins_sync ON goal_checkins (updated_at);
  CREATE INDEX checkins_kr ON goal_checkins (kr_id, at);
  ```
