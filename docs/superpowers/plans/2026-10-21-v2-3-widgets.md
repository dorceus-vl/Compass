# Compass v2.3 (iPhone and iPad widgets) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seven WidgetKit widgets for the Compass iOS app (iPhone and iPad), as approved in the preview (`docs/widgets-preview.html`):
- Today: small, medium (tick to complete) and large (by horizon, with Blocked);
- Quick add (small);
- Project pulse (medium, configurable);
- the Lock Screen inline, circular and rectangular widgets;
- iPad extra large "This week".

**Architecture:**
- **Snapshot:** after each sync, and after a local edit, the web app inside the Capacitor shell builds a small **widget snapshot** on the device (a pure `buildWidgetSnapshot`). It hands the snapshot to native code through a new `CompassNative.updateWidgets` call. Native code writes it to the existing App Group container (`group.com.knocturnlabs.compass`) and reloads the widgets' timelines.
- **Widget extension:** a new `CompassWidgets` extension (SwiftUI and WidgetKit, iOS 17) reads only that file. It makes no network call to read.
- **Tick to complete:** an App Intent posts to a new, narrow server route with a **widget token**. The token can only mark one of Vlad's tasks done; it is created per device with the passkey step-up and can be revoked in Settings. If the call fails, the tick is queued in the App Group, and the app sends it the next time it opens.
- **Taps:** they open universal links (`https://compass.knocturnlabs.com/...`), which the shell already routes in-app.

**Tech Stack:** As before. Swift (WidgetKit, AppIntents, SwiftUI) inside `mobile/ios`. No new npm dependency and no new Pod.

**Spec:** Vlad's request ("iPad and iPhone widget") and the approved preview (artifact https://claude.ai/artifact/CB4R7wL5GWxCNGfxZwvesr, copied to `docs/widgets-preview.html`), plus the Phase 4 native rules in `CLAUDE.md`.

## Global Constraints

- The Phase 4 native rules hold: the shells bundle no app code, navigation is locked to the Compass host, and native rule changes ship with `npm test` checks. Never bundle `web/dist`.
- **What a widget may show:**
  - A snapshot holds at most 20 tasks, 10 projects, 7 days of counts and one next milestone per project; there are no notes, checklists or people.
  - Tasks from **Offline-only projects** appear only as counts, never with a title, in any widget.
  - **Work titles on the Lock Screen** (the accessory families) are replaced by "Work task" while the setting `widgets.hide_work_on_lock` is on (default on). On the Home Screen they show their titles (the phone is unlocked).
  - The snapshot file is written with `FileProtectionType.completeUntilFirstUserAuthentication` and holds plain text (it's on Vlad's own device, like the web mirror).
- **Widget token:**
  - It's a random 256-bit secret, shown to the device once and stored only in the shared Keychain (access group for the app and the widget extension), and stored on the server only as a SHA-256 hash.
  - Its scope is exactly one action: mark a live, open task done.
  - One token per device. Creating one needs the passkey step-up; revoking is plain. It is listed in Settings → Widgets.
  - Every use writes an audit row (actor `widget`, no task text), with the limits of 60 a minute and 300 a day.
  - The `task_events` row of a widget tick has actor `you` (it is Vlad ticking) and data `{ via: 'widget' }`. The actor CHECK in `0002_core.sql` stays as it is, so no table is rebuilt (W5).
- **Kelly** sees nothing new. The agent API is unchanged.
- **Migration:** `0016_widgets.sql` only, never edited after commit.
- No new dependency. Never deploy, push, put secrets, sign for a real device or install on Vlad's devices. Simulator builds (`npm run build:sim`) and `xcrun simctl` screenshots are fine, and so is creating a simulator if none exists.

## Rulings made while writing this plan

- **W1: the snapshot shape** (`shared/widget-snapshot.ts`, pure and tested):

  ```
  { v: 1, at, tz, today: { due, late, done, total, next: Item|null },
    items: Item[≤20],
    horizons: { short: Item[], medium: Item[], long: Item[] },
    blocked: number,
    projects: { id, name|null, rag, pct, next_milestone: { name|null, late_days }|null, slip_days|null, high_risks, overdue, work, offline }[≤10],
    week: { day, short, medium, long }[7],
    lock: { hide_work: boolean } }
  ```

  where `Item = { id, title|null, due_label, late, horizon, work, offline, project }`. An Offline item has `title: null`, and so does an Offline project's name and milestone name.

  The rules are the ones Today uses: due today or overdue, not done, top-level, not blocked, and blocked ones counted apart. High risks come from the cached RAID if present (otherwise null).
- **W2: when it's written.** After every successful sync pull, after every local task edit (debounced 2 s), at app start and when the app comes to the foreground. Only in the iOS shell (`isNativeIOS()`); elsewhere `updateWidgets` is a no-op. The native side writes the file atomically and calls `WidgetCenter.shared.reloadAllTimelines()`.
- **W3: widget timelines.** Each widget reads the file. The timeline refreshes `.after(now + 15 min)`, plus one entry at local midnight so "Today" rolls over. With no file yet (never opened, or signed out), the widget shows a placeholder: "Open Compass once to fill this widget".
- **W4: taps.**
  - Today, task rows and Lock Screen → `https://compass.knocturnlabs.com/` (Today) or `/?task=<id>` (v2.1's deep link).
  - Project pulse → `/projects/<id>/dashboard`.
  - Quick add → `/?quickadd=1`; Ask Athena → `/athena`.
  - These are universal links, handled by the existing scene delegate and `CompassLink`, so they never leave the Compass host.
- **W5: tick to complete.**
  - Migration `0016_widgets.sql` creates `widget_tokens(id, device_name, token_hash UNIQUE, created_at, last_used_at, revoked_at)`.
  - `task_events.actor` keeps its CHECK (`you`, `rule`, `kelly`, `meeting`). A widget tick is written as `you` with data `{ via: 'widget' }`, so `task_events` is not rebuilt (verified 2026-10-21: the CHECK exists, and rebuilding the biggest table for a label isn't worth it).
  - Routes:
    - `POST /api/widget/token { device_name }` (session plus step-up) returns `{ id, token }` once.
    - `DELETE /api/widget/token/:id` revokes.
    - `GET /api/widget/tokens` lists them (no secrets).
    - `POST /api/widget/tasks/:id/done` (`Authorization: Bearer <token>`; the auth guard carve-out is exactly this path, like `/api/agent/*`) uses the existing `completeTask(env, task, [], 'you')` with the event data `{ via: 'widget' }` (extend `completeTask` with an optional data argument if it has none), so recurrence and the unblock push run as usual.
  - Refusals: 401 for a bad or revoked token (no audit), 404 for a missing, trashed or done task, 429 over the limits.
  - The App Intent runs `markDone(id)`. It flips the item in the local file at once (optimistic) and posts. On a network failure it appends `{id, at}` to `pending-ticks.json` in the App Group; the app reads and clears it in `takeWidgetTicks()` (a new plugin method) and sends them through the normal offline queue.
- **W6: Keychain.** The token lives in a Keychain item with the access group `$(AppIdentifierPrefix)com.knocturnlabs.compass.shared` (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`), written by the app (plugin method `setWidgetToken(token)` after the web app gets it from the route) and read by the widget's intent. The web app never stores the token itself.
- **W7: colours and type in Swift.** A `Theme.swift` holds the DESIGN.md tokens (the hex values copied exactly, with a comment naming DESIGN.md). It uses the system font, and SF Mono for labels, since widgets can't load Google Fonts. It covers dark only, matching the app, with Lock Screen accessory views in the system's vibrant rendering.
- **W8: settings.**
  - `Settings.widgets = { hide_work_on_lock: true }`.
  - Settings → Widgets (shown only in the iOS shell) has that switch, "Tick tasks from widgets" (creates a token with step-up and stores it through `setWidgetToken`, or revokes), and the list of devices with tokens.

- **A5 Token:** sealed with an Android Keystore AES-GCM key (`compass_widget_token`); the web layer never reads it back.
- **A6 Taps:** immutable `PendingIntent`s open the main Activity on an https Compass URL, routed by `CompassLink.java`.

Built in `mobile/android/app/src/main/java/com/knocturnlabs/compass/widgets/` (commits `349c233` and the fix `c9c7116`). Changes from the rulings as built: rows are added views with their own immutable intents (no `RemoteViewsService`, so no `FLAG_MUTABLE` anywhere); the tick POST is a plain TLS socket so the web view's cookies never go with it; one inexact alarm refreshes the widgets at local midnight.
