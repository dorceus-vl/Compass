# Compass

Knocturn Labs task and project-management app, for Vladimir only. Spec: `docs/superpowers/specs/2026-10-19-compass-design.md`.
Catalogue of everything planned: `docs/compass-features.md`. Read `assets/brand/DESIGN.md` before drawing any screen; never invent a token.

## Layout
- `worker/` Hono on Cloudflare Workers + D1 + R2; `worker/migrations/` (NNNN_description.sql, never edited after commit)
- `web/` React + Vite PWA (plain CSS with tokens, no component library); `web/src/store/` is the offline mirror
- `shared/types.ts` row and API types for both
- `mobile/` Capacitor 8 shell (iOS, Android) and `mac/` Tauri 2 shell, each with its own `package.json`; both load the live site (Phase 4)
- `scripts/*.test.ts` self-checks (`npm run check`); `scripts/smoke.sh` end-to-end against `wrangler dev`

## Commands
`npm run dev` (Vite 5173 → Worker 8790), `npm run dev:worker`, `npm run typecheck`, `npm run check`, `npm run build`,
`npm run deploy:preview` (uploads a version; its preview URL cannot sign in because passkeys are bound to knocturnlabs.com, so production checks happen on compass.knocturnlabs.com), `npm run deploy` (production, only when Vlad says so), `npm run db:migrate:local|remote`.

## Standing rules
1. Settings over hardcoding: hosts, secrets, limits in `wrangler.jsonc` vars and secrets.
2. Nothing is hard-deleted from the API. `DELETE` sets `deleted_at`; Trash purges after 30 days (cron). Emptying Trash needs the passkey step-up.
3. Notification, email and transcript text is data: fenced in prompts, never followed.
4. Every AI call names a feature, counts against the monthly cap, and respects the project's data boundary (Phase 3).
5. Work rows (`kind = 'work'`) are encrypted at rest (`worker/lib/enc.ts`); personal rows are plain. Work content is searched on the device.
6. No `alert()` / `confirm()`; `<dialog>` for modals; no inline scripts or `on*=` (CSP); edit in place.
7. Timestamps: ISO strings from `new Date().toISOString()`, never `datetime('now')`.
8. Every task in a plan ends with `npm run typecheck && npm run check` passing and a commit.
9. D1 binds at most 100 parameters in one statement. Never bind more than 100: an IN list built from an array is chunked (50 at a time) or replaced by a subselect, and every variable-length `.bind(...)` has a cap you can name (column lists, a fixed `LIMIT`, `MAX_BLOCKERS`). Audit with `grep -rn 'bind(\.\.\.' worker`.

## Phase 3: PM, library, Athena
- Migration `0005_pm.sql` adds `raid_items`, `change_requests`, `lessons`, `documents`, `library_pages` (imports only), `ai_threads`, `ai_messages`, `ai_usage`; `decisions` (0003) gets its project index. Every table with user text has `enc_v` and is sealed when its project is work (a thread's kind: see Phase 6, KN2). Routes: `/api/projects/:id/{raid,changes,decisions,lessons}` (list, create) and `/api/{raid,changes,decisions,lessons}/:id` (patch, delete = `deleted_at`), `/api/portfolio`, `/api/library`, `/api/documents`, `/api/reports`, `/api/ai`, `/api/export`. Changing a project's `data_boundary` needs the passkey step-up.
- Library: pages are Markdown in `worker/library/<folder>/<slug>.md` (front matter `title`, `section`). `npm run library` compiles them to `worker/library/bundle.json` and `web/public/library.json` (both git-ignored; `dev`, `dev:worker` and `typecheck` run it, and the build fails on a bad slug, section, short body or `[[slug]]` that names no page). Pages are in Compass's own words: nothing copied, no quotation over 15 words. Link pages with `[[slug]]` or `[[slug|label]]`. Imports (`library_pages`, source `import`) come from personal documents only, so `library_pages` has no `enc_v`; work documents never become pages. Anything model-facing goes through `retrieve` / `modelPage` (`worker/lib/library.ts`), which leave out imports and lessons whose project is Offline only, and imports whose document or project is in Trash; the device search still sees them.
- Athena (the user-facing name of the copilot; internal ids stay `copilot`, `/api/ai`, `ai_threads`, `PresetId`): every route that builds a prompt (`POST /api/ai/chat`, `POST /api/ai/brief`, the status report summary in `POST /api/reports/status`) refuses Offline-only content before anything is stored or sent: chat resolves the project with `projectAccess` and answers 409 `offline_boundary`; the brief leaves out items of Offline (or trashed) projects; the report returns its data with `ai_refused: 'offline_boundary'` and no summary. `projectContext` itself also reads only a live cloud project. Every model call goes through `runAi` (`worker/lib/ai.ts`): names a feature, checks the monthly cap (`ai_monthly_cap_micro` setting) and 30 calls an hour, writes an `ai_usage` row and an audit row with no content. Don't add a model call that skips it. `AI_STUB=1` (with `DEV_LOGIN=1`) answers from a stub and is for local tests only; never set it in `wrangler.jsonc`. Keys `ANTHROPIC_API_KEY` and `GEMINI_API_KEY` are Worker secrets that Vlad puts himself; model ids (`AI_MODEL_CLAUDE`, `AI_MODEL_GEMINI`) and prices (`AI_PRICES`) are vars. Proposals are only written to the board when Vlad taps "Add to the board".
- Documents: uploads are checked by name, declared type and first bytes, and streamed privately to R2 (`docs/<id>`), never inline. Work-project files are sealed in R2 and capped at 10 MB; other files at 20 MB (`worker/lib/uploads.ts`). `.docx` reading caps parts at 10 MB, 20 MB in total and 20 headers (`worker/lib/extract.ts`). Reports, Markdown and Word files are generated on the device (`web/src/docs/`, `shared/report-model.ts`); `buildReportModel` takes the time zone, so pass `settings.tz`. Templates are your own `.docx` with `{{placeholders}}`.
- Export: `GET /api/export` is JSON of everything you own, work rows opened, and needs the passkey step-up. It leaves out sessions, push subscriptions, audit, `ai_usage` and R2 keys.

## Phase 4: native apps
- `mobile/` (Capacitor 8: iPhone, iPad, Android) and `mac/` (Tauri 2) are shells around the live site: they load `https://compass.knocturnlabs.com` and bundle no app code: iOS and Android carry only `mobile/www/offline.html` (shown when the site can't load) and a placeholder `mobile/www/index.html` Capacitor needs; the Mac bundles nothing and shows a blank window when offline. Never bundle `web/dist` into a shell: the app needs same-origin `/api` and its HttpOnly cookie. `COMPASS_URL` points a local build at dev; rebuild or `npm run sync` without it before anything else (the Android release build refuses a config that isn't production over https). App id `com.knocturnlabs.compass`, scheme `compass`, Apple team `K948BT44PM`. Their dependencies stay in their own `package.json`; nothing from `@capacitor/*` or `@tauri-apps/*` reaches the Worker or web app.
- Sign-in in a shell only through the system sheet (iOS), a Custom Tab (Android) or the default browser (Mac): Knocturn ID at `id.knocturnlabs.com` with PKCE, `redirect_uri=compass://auth`, then `POST /api/auth/native {code, code_verifier}` (the only new unauthenticated route). Never a password field or an embedded web view for sign-in. Native code refuses sign-in URLs not on `id.knocturnlabs.com` and callback schemes other than `compass`; the callback is exactly `compass://auth?code=&state=`.
- The native contract lives in `web/src/native.ts` (the only caller; the table is in its header). Capacitor plugin `CompassNative`: `signIn`, `registerPush`, `takeSharedText`, `openExternal`; events `sharedText`, `notificationTap`. Tauri: commands `open_external`, `notify_permission`, `notify`, `close_quick_add`; event `compass-auth`. Change a method on both sides (Swift, Java, Rust) and in `scripts/native.test.ts` together.
- Navigation is locked to the Compass host on every path (links, `window.open`, redirects, notification taps, universal and App Links): other http(s) pages open in the system browser, mailto/tel in their apps, other schemes nowhere. The rules are in `CompassLink.swift`, `CompassLink.java` and `mac/src-tauri/src/link.rs`, with self-checks (`npm test`). The Mac capabilities let only the Compass origin invoke commands and listen to events.
- Device push: `push_subscriptions.kind` is `web`, `apns` or `fcm` (`worker/lib/apns.ts`, `fcm.ts`, sender `notify.ts`). Push text carries no work content. A missing secret, or Apple/Google refusing our credentials (APNs 403, BadTopic, TopicDisallowed, 429 TooManyProviderTokenUpdates; FCM 401/403), counts as `'local'`: nothing is counted against the device and no device is deleted (only the device's own gone/failed answers delete or count; 10 failures in a row delete). Every push also lands once in the outbox, whether or not a device is reachable. The Mac registers no token (`thisDeviceId()` is `'local'`): it reads `GET /api/push/outbox` once a minute while signed in and Notifications are on, and shows banners through `UNUserNotificationCenter`.
- Push secrets are Worker secrets Vlad puts himself: `APNS_KEY_P8`, `APNS_KEY_ID`, `FCM_SERVICE_ACCOUNT` (never in git, `.dev.vars` examples or chat). Vars in `wrangler.jsonc`: `APPLE_TEAM_ID`, `APNS_TOPIC`. Android's `google-services.json` is Vlad's too.
- Trust files live in `web/public/.well-known/` (`apple-app-site-association`, `assetlinks.json`); they are served as JSON by the Worker's static assets. A new signing key (release keystore, Play) means a new fingerprint in `assetlinks.json` here and in the knocturnlabs.com repo.
- Commands (need CocoaPods, Java 21, the Android SDK and Rust). In `mobile/`: `npm install`, `npm run sync` (production config, both platforms), `npm run build:sim` (ad hoc signed simulator build into `build/`, so the app group works), `npm test` (Swift and Java rule checks), `npm run build:android` (sync + `./gradlew assembleDebug`, Java 21), `cd android && ./gradlew assembleRelease` (guarded by `checkReleaseConfig`; an unsigned APK until a release keystore and `signingConfig` exist), `npm run open` (Xcode). In `mac/`: `npm install`, `npm test` (`cargo test`), `npm run build` (`tauri build --bundles app` into `src-tauri/target/release/bundle/macos/Compass.app`). Build and install steps are in `mobile/README.md` and `mac/README.md`.
- Never commit: `mobile/ios/App/Pods`, `google-services.json`, `*.jks` / `*.keystore`, `mac/src-tauri/target`, `.app` / `.apk` / `.aab`, DerivedData. Deploying the Worker or the outside repos, putting secrets and installing on Vlad's devices happen only when Vlad says so.

## Phase 5: Kelly
- Kelly (Vlad's assistant, in Kelly-Cloud) uses Compass through two doors. In: `/api/agent/*` (`worker/routes/agent.ts`, `worker/lib/agent.ts`). Out: the relay to Kelly-Cloud's `/api/compass-relay` (`worker/routes/kelly.ts`). Contract for both: `docs/integration.md` (Agent API, Relay). Vlad's side: Settings → Kelly (`GET`/`PUT /api/kelly`, `GET /api/kelly/log`), Kelly's brief on Today, Kelly's events on Calendar, "Also let Kelly search it" on a document import.
- Boundary: the agent API only returns or touches shared items: a task with no project only if it is personal; a task or project only if its project is live (not in Trash) with `data_boundary = 'cloud'`. Everything else is a 404 as if missing and counts only as the number `hidden`. Only top-level tasks (a subtask is invisible). Work-and-cloud tasks Kelly creates are sealed like any work row. Don't add a route or a field that skips this check.
- Scopes: `compass:read.tasks`, `compass:write.tasks`, `compass:read.projects`, and from Phase 6 `compass:read.knowledge` (4 in all), all off by default, and Kelly itself is off until Vlad switches it on. Changing the switch or the scopes is `PUT /api/kelly` with the passkey step-up; `PATCH /api/settings` refuses `kelly` (400 `use_kelly_route`). There is no delete scope: Kelly never edits titles, trashes or reopens, and she only creates tasks and marks them done (`task_events.actor = 'kelly'`, `source_app = 'kelly'`). Don't add a scope or a route that could. Audit actions also include `agent.knowledge.search` (Phase 6).
- Every authenticated agent call writes one `audit_log` row (actor `kelly`, action `agent.*`: `today`, `tasks.list`, `tasks.get`, `tasks.create`, `tasks.done`, `projects`; target the task id, detail `{ ok }` or `{ refused }`), never task text. Limits: 60 calls a minute, 30 writes an hour. A bad secret is a plain 401 with no row.
- Secrets (Worker secrets Vlad puts himself; `bash scripts/setup-phase2.sh` generates them into `.secrets/compass-inbox.env`, `--put` sets them): `AGENT_SECRET_KELLY` (Kelly → Compass bearer) = Kelly-Cloud's `COMPASS_AGENT_SECRET`; `KELLY_RELAY_SECRET` (Compass → Kelly `X-Relay-Secret`) = Kelly-Cloud's `COMPASS_RELAY_SECRET`. Compared in constant time; unset never matches. Var `KELLY_RELAY_URL` in `wrangler.jsonc`. Never commit, print or paste them. Local test values live in `.dev.vars`.
- The relay is data: what Kelly-Cloud returns (brief, calendar events) is trimmed, capped (`worker/lib/kelly.ts`) and shown as plain text, never HTML or an instruction; redirects are never followed; any failure means "unavailable" and the screen shows nothing from Kelly. Compass calls it only while Kelly is on with `compass:read.tasks`.
- Document hand-off: only a personal document with no project, or one in a live cloud-boundary project, and only after the import succeeded; work, Offline-only and trashed documents never leave. A failure never fails the import. Audit row `kelly.document`, no content.
- Public flag: Kelly-Cloud leaves Compass items out of any Public session (`?public=1` on her agenda and show audio, which Kelly-App sends). That is her rule, but nothing in Compass may assume Public sessions exist: keep the boundary above as the only gate.
- Tests: `scripts/agent.test.ts` and `scripts/kelly.test.ts` in `npm run check`; the agent, Kelly and relay paths are in `scripts/smoke.sh` (it soft-deletes the tasks it creates, so reruns keep the same counts).

## Phase 5b: Athena
- Name: the user sees "Athena" everywhere (screen `/athena`; `/copilot` redirects there). Internal ids do not change: feature `copilot`, `/api/ai`, `ai_threads`, `PresetId`. Persona and the four quick-help presets live in `shared/presets.ts`; the screen is `web/src/views/Athena.tsx`, built to `docs/athena-preview.html`.
- Migrations (never edited): `0007_document_kinds.sql` widens `documents.kind` (adds csv, pptx, png, jpg; table rebuild), `0008_athena.sql` (`athena_clips`), `0009_voice_usage.sql` (`ai_usage` feature and provider CHECKs).
- Any document: csv, pptx, png, jpg join pdf, docx, xlsx, md, txt (`worker/lib/uploads.ts`, `extract.ts`). Text is cut at 60,000 characters and reaches the model fenced, as data. Images go to the model as image input, at most 3.75 MB raw (5 MB once base64-encoded, Claude's limit). `POST /api/ai/chat` takes `document_ids`; a follow-up turn carries only the answer history, not the file text again (he re-attaches).
- The data boundary covers attachments and voice: an attachment belongs to the thread's project, or is unfiled while the thread is personal; a work document never joins a personal thread; Offline-only or trashed content never reaches a model or ElevenLabs. Refusals: 409 `offline_boundary` (the project), 409 `document_boundary` (an attachment). The check is on the server, before anything is stored, sent or metered.
- Avatar: loops (`idle`, `listening`, `thinking`, `speaking`) and a still portrait are Vlad's own media in private R2 (`athena/<id>`), rows in `athena_clips` (not encrypted). Routes under `/api/athena`: `GET /clips`, `POST /clips`, `DELETE /clips/:id`, `POST /portrait`, `DELETE /portrait`, `GET /media/:id` (Range, 206 and 416). A removed clip gets `deleted_at`; the cron purges the file after 30 days. Settings → Athena holds the upload, the portrait and the voice.
- Voice: `POST /api/athena/speak` (an answer's `message_id`, cached in R2 per message, sealed for a work thread; or `{test:true}`) and `POST /api/athena/listen` (raw `audio/webm` or `audio/mp4`, 2 MB and 60 s at most; the text goes into the Ask box and is never sent by itself). ElevenLabs is called only from the Worker (`worker/lib/voice.ts`), never from the browser. Both resolve the project boundary on the server before the body is read or anything is metered (a thread's project wins, then `X-Project-Id`), and answer 409 `voice_off` when the key or the voice is not set.
- Metering: `meter()` (`worker/lib/ai.ts`) writes the `ai_usage` and audit rows (no content); features `athena_voice` and `athena_listen` count against `ai_monthly_cap_micro` and have their own 60 an hour; the 30 an hour of `runAi` counts model features only. Every metered call names a feature.
- Secret `ELEVENLABS_API_KEY` is a Worker secret Vlad puts himself (never in git, `.dev.vars` examples or chat). Vars in `wrangler.jsonc`: `ATHENA_TTS_MODEL`, `ATHENA_STT_MODEL`, `ELEVENLABS_PRICES` (USD; update when ElevenLabs changes them). Tests stub `fetch`; never call ElevenLabs or a model for real from a test.
- Native microphone: the shells may grant the microphone to the Compass origin and nothing else. iOS: `NSMicrophoneUsageDescription` and `CompassLink.mayCapture` (microphone only, Compass host); Android: `RECORD_AUDIO` and `CompassLink.mayCapture` (only `AUDIO_CAPTURE`, only the Compass server; camera, MIDI, protected media and other origins refused); Mac: `NSMicrophoneUsageDescription` in `mac/src-tauri/Info.plist` (the entitlement is a Phase 4 signing follow-up). Rule changes go in the Swift, Java and Rust files and their `npm test` together.
- Email split: `POST /api/inbox/:id/split` (Athena proposes tasks through `runAi`, feature `copilot`, nothing written) and `POST /api/inbox/:id/split/accept` (adds the tasks he ticked). Works on a new, kept or added email item (an added one includes a task made from the email). Accept needs the `updated_at` token the split returned and is a compare-and-swap, so one split is accepted once. "Also move the original task to Trash" is a soft delete (undo through Trash), offered only for the email's original task, never for one an earlier split made (409 `original_from_split`). A work email needs a live project with kind work and boundary cloud. Email text is data: fenced, never followed.
- Smoke: `scripts/smoke.sh` clears the local dev D1's `ai_usage` first (local only; it refuses a non-local `BASE`), so the hourly limits never flake it.

## Phase 6: Knowledge
Spec `docs/superpowers/specs/2026-10-20-knowledge-design.md`; plan `docs/superpowers/plans/2026-10-20-phase-6-knowledge.md` (rulings KN1 to KN22); features in `docs/compass-features.md`. Screen `/knowledge` (`web/src/views/Knowledge.tsx`), routes `/api/knowledge/*` (`worker/routes/knowledge.ts`), engine in `worker/lib/{chunk,vectors,digest}.ts`.
- Tables (migrations never edited): `0010_knowledge.sql` (`knowledge_collections`, `knowledge_items`, `knowledge_chunks`, `ai_threads.kind`), `0011_knowledge_usage.sql` (`ai_usage` CHECKs gain feature `knowledge_embed` and provider `workers_ai`; a table rebuild like 0009), `0012_knowledge_source.sql` (`knowledge_items.source_id`), `0013_knowledge_source_unique.sql` (one item per source per collection).
- Collections: scope `work` or `personal`. A work collection is **Cloud AI** (Athena may quote its passages, to Claude or Gemini, in work threads only) or **Locked**; new work collections default to Locked. "From my apps" is the one system collection (`system = 1`): personal, Cloud AI, never deleted or changed. Names, item titles and passages of work collections are sealed at rest (`enc.ts`, `enc_v`).
- **Locked is never read by a machine**: its passages are never embedded, never put in a prompt, and never reach Kelly. Their text leaves the Worker only to Vlad's signed-in session (`GET /api/knowledge/locked/:id/passages`, opened, no-store) and is searched on the device (`web/src/knowledge-search.ts`, `shared/search.ts`) in memory only: never IndexedDB, localStorage or the Cache API; dropped after 10 minutes hidden and on sign-out (the Locked results on the screen go with it).
- **Work stays work (KN2)**: a work passage only reaches a work thread. `ai_threads.kind` ('personal' or 'work', nullable = derived) replaces the old rule "a thread with no project is personal": the effective kind is the project's kind when there is a project, else `kind`, else personal. Athena's picker offers "No project (work)". A personal thread naming a work collection is 409 `knowledge_boundary`. A knowledge query that hits the limit makes Athena answer without knowledge and say so. "Add to the board" sends `from_message` (the answer's id) with `POST /api/tasks`: the server takes the task's project and kind from that answer's thread and ignores the body's (KN22), so a "No project (work)" thread makes sealed work tasks.
- An unfiled document whose only live knowledge items are in Locked collections is never read by a model: Athena refuses it as an attachment and a Cloud AI collection refuses it (both 409 `knowledge_boundary`) unless the add carries the passkey answer (`X-Step-Up`) (`lockedOnly`, KN22).
- Step-up (passkey) for: Locked to Cloud AI (also at creation of a work collection as Cloud AI), deleting a collection, and turning on Kelly's `compass:read.knowledge`. Cloud AI to Locked deletes the vectors at once.
- Binding and vars (KN1): `AI` (Workers AI, `@cf/baai/bge-m3`, 1024 dims) and `VECTORIZE` (index `compass-knowledge`, cosine; a metadata index on `collection_id` as a string must exist before any upsert), both optional in `Env`. Var `KNOWLEDGE_PRICES` = `{"embed_per_1k_tokens":0.000012}` (USD; bge-m3 is $0.012 per million tokens). Without the bindings (local) `worker/lib/vectors.ts` stands in: with `AI_STUB=1` embeddings are deterministic hashes and the vectors live in memory per isolate (a restart loses them; the smoke re-embeds). Local tests never call Workers AI or Vectorize.
- **`npm run dev:worker` runs `wrangler dev --local`**: with the `ai` and `vectorize` bindings in `wrangler.jsonc`, plain `wrangler dev` opens a remote proxy session (AI) and defines VECTORIZE as a proxy that throws, which would touch Cloudflare. Keep `--local` on every local run (the smoke refuses a non-local `BASE`).
- Metering: embedding is feature `knowledge_embed`, through `meter()` (one call per ingest batch, one per question that embeds its query). It counts against `ai_monthly_cap_micro` (409 `cap_reached`); query embeds have their own 120 an hour (429 `rate_limited`); background ingest batches skip the hourly check (KN14/KN15: a big drop never blocks search) and stay out of the 30 an hour of `runAi`.
- Search (KN4): Vectorize topK 40 filtered by `collection_id` `$in` the allowed list, open the passages, BM25 rerank, top k (6 for Athena, 10 on the screen). Allowed = live, personal or Cloud AI, and every LIVE rule below is re-checked in D1 after Vectorize answers, so a stale vector can't leak. Don't add a model-facing path that skips `hybridSearch` / its collection list.
- Ingest (KN5): a file is uploaded through the documents pipeline (`POST /api/documents`, private R2), then `POST /api/knowledge/items {collection_id, document_id}` extracts and chunks within the request (about 3,200 characters, 200 overlap, at most 2,000 passages per item; locators `p. N`, `slide N`, `Sheet!A1:F40`, `§ heading`, `part N`), store passages with `embedded = 0`, and embed in `waitUntil`; the 15-minute cron finishes the rest. State: `indexing`, `ready`, `failed`. Every kind is cut at 200,000 characters (a PDF across its pages; a workbook at its own cap); a cut item says "Indexed in part (file too long)". A batch Workers AI refuses is split down to single passages; a passage it still refuses marks its item `failed` ("Couldn't index part of this file") and the rest go on; when nothing answers, the run pauses for the cron (KN22). Locked items go straight to `ready`. The document-upload flag `knowledge_work=1` seals an unfiled upload (no project) as work, so it can join a work collection. Items from a document follow it: a work-project document can't go to a personal collection, and a document whose project turns Offline-only or goes to Trash leaves search and loses its vectors (sweep in the cron).
- Sources (KN16): items saved from a meeting review, an email or Athena carry `source_id`; LIVE and the sweep follow it to the meeting review's project or the email item's task's project, so they leave search and lose vectors the same way. Saving the same source into the same collection twice returns the existing item. Email saved from a task in a work project is sealed; an email kept as a work task, or a task moved into a project, runs the sweep (`unembedStale`, which seals turned-work copies) at once, not only at the cron.
- Purge (KN17/KN18): when the Trash purge removes a project, knowledge items whose source (meeting review or email task) pointed to it are purged in the same batch, with their vectors; when it removes a task, email knowledge items whose inbox row points to that task are purged too if the task's project is Offline-only or itself being purged (otherwise they stay: their content was already allowed). Purge order: chunks, items, collections, then documents. Trash lists items and collections; an item or collection in Trash leaves search at once and is purged with the rest after 30 days.
- The Knowledge screen searches on Enter, or after an 800 ms pause once 3 characters are typed (each search is one of the 120 query embeds an hour). "Ask Athena about this" opens `/athena?knowledge=<id|all>` with the question in sessionStorage (read once, then cleared), never in the URL.
- "From my apps" (KN7, `worker/lib/digest.ts`): once a day at `digest_hour` (and "Refresh now", at most every 10 minutes) Compass builds its own personal digest and pulls Finance, Health, Home and Hollow from Kelly-Cloud's `GET /api/compass-relay/apps-digest` (contract in `docs/integration.md`). One item per source, replaced all or nothing (the new item is ready before the old one goes; a failed source keeps yesterday's item with the reason on it). A same-day retry runs hourly and refreshes only the sources that failed. The relay answer is read up to 200 KB. Digests carry no account or card numbers and never a medication name (counts only); they are fenced as data wherever a model reads them.
- Kelly (KN8, KN20): scope `compass:read.knowledge`, `GET /api/agent/knowledge/search?q=&limit=` (personal live Cloud AI collections only, "From my apps" included; the ids come from D1, never the request). Contract in `docs/integration.md`. Kelly-Cloud's tool is `compass_knowledge_search`. The apps-digest refresh runs whether Kelly is on or off (KN21): it only reads Vlad's own data into his personal collection; nothing leaves Compass.
- Export: `GET /api/export` includes the three knowledge tables with work text opened.

- Dependencies: `tasks.blocked_by` is a JSON array of at most 20 task ids (`shared/deps.ts`). A blocker must be a live task of the same kind as the task (400 `bad_dependency`; so is a link left across kinds when a project move changes a task's kind); a loop is refused with 409 `dependency_cycle` (the graph includes trashed tasks' edges, so a loop can't close behind one). A trashed or done blocker counts as resolved. Completing the last open blocker sends one `unblocked` push (`notifyUnblocked`, called from `completeTask`, honours `settings.push.unblocked` and quiet hours); the text carries the task title only for a personal task, "A task is unblocked" for work. Blocked tasks show a chip (Board, List, Today), sit in a collapsed "Blocked" group on Today, and draw as arrows on the Timeline (also under reduced motion; only animation is off). Templates never carry `blocked_by` (ids are per instance, V10).
- Checklists: `tasks.checklist` is a JSON array of `{ id, text, done }`, at most 50 items of 200 characters (`parseChecklist`, 400 on a bad shape); it is sealed with a work task (`TEXT_COLS`, `ENC_COLS.tasks`). A recurring task's next occurrence gets the same items unticked (`untickChecklist`, V4). The editor (`web/src/ui/Checklist.tsx`) saves the whole list as one `updateTask` through the offline queue; it adopts a value from the server only if it hasn't been seen and no edit of ours is pending (`shouldAdoptChecklist`). Reorder is buttons and Alt+Up/Down (V14), no pointer drag.
- Templates (`/api/templates`, `worker/routes/templates.ts`, `shared/templates.ts`): table `templates` (scope `task` or `project`, kind, body JSON, `name` and `body` sealed for work). Built-ins (Project kickoff, Vendor onboarding, Change / release) are code in `shared/templates.ts`, never stored. A template keeps day offsets from the earliest date, checklists unticked, parent links by index, no ids and no `blocked_by`; at most 200 tasks and 50 milestones. Apply is one `DB.batch` (project, milestones, tasks, `task_events` with `{from:'template'}`), sealed with the destination kind. Same-kind rule: a work template can't go to a personal project or kind (400 `template_kind`); a built-in takes the kind Vlad picks. Apply and Save as template are online-only actions (V15), disabled offline with a plain line. Deleting sets `deleted_at`; templates are listed in Trash with Restore and purged after 30 days.
- Meeting series (`worker/lib/series.ts`, `shared/series.ts`, `/api/meetings/series`, `/meetings/series/:id`): recurring meetings that share a title once dates and numbers are stripped, grouped per project or unfiled. `meeting_series.key` and `id` are HMAC-SHA-256 values under a key derived (HKDF) from `COMPASS_DATA_KEY`, so a work title's words never sit in plain D1 (V13). **Rotating `COMPASS_DATA_KEY` changes every key and id**: a rotation procedure must re-key `meeting_series` (key, id, `meeting_reviews.series_id`) together with re-sealing, or new meetings open second series beside the old ones (`enc.ts` has no rotation story yet). `name` and `answered` (question hashes) are sealed for work; a personal-project series is plain. Accepting an action item sets the task's `source_ref = meeting:<review id>:<index>` (V7); tasks without a `source_ref` are matched by project and `source_url` starting with the review's url (the fallback for older tasks). A review that has a series is never re-keyed by ingest, so a hand-moved meeting stays put; the Trash purge clears `series_id` and deletes the series of a purged project (FK). The agenda ("Prepare next session": Copy, Markdown, Word) is built on the device; "Ask Athena to write it" puts the text in sessionStorage (`athena:ask`) and opens `/athena?agenda=<project id | work>`, never the text in the URL. Answering a question and moving a meeting are online-only.
